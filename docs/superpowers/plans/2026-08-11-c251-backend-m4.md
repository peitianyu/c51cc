### 深度分析: 常量折叠为何不安全 (101_fold_offset 专项测试实证)

**主因: 编码缺失 (sim251 mov_dis 只有字节级)**
- 位移寻址家族 (0x09/0x19/0x29/0x39/0x49/0x59/0x69/0x79): sim251 只实现
  0x09 (字节读), 0x19 (字节写), 0x69/0x79 (far DRk); **字级 0x29/0x39 未实现**
  ("default: break" 静默跳过!)。
- 折叠 int 数组 (字访问) 触发不存在编码 → encode 返回 -1 (unsupported) →
  **指令被静默丢弃** → 读值错误 (48_ptr_arith ret=128, 专项 ret=120 = 8|16|32|64 全字访问)。
- 修复: 折叠限字节访问 (fold_ok 加 size<=1); 字级需先实现 sim251 0x29/0x39。

**次因: 地址语义 (已防护)**
- 折叠的 OFFSET dest 只含基址 (不含 off), 访问靠 @WRj+off 补偏移。
- 若 dest 被非 LOAD/STORE 消费 (加法/比较/传参) → 未加偏移地址 → 错。
- 防护: 块内 use 全为 LOAD/STORE 的 ptr + global_live 检查 (跨块不折叠)。

**编码劫持 bug (调试发现)**
- parse_indirect_wr_off 对无偏移 "@WRj" 返回有效值 → 普通字读 @WRj 被劫持
  到字节位移分支 → unsupported。修复: 无偏移返回 -1。

## 常量折叠链断裂修复 (208b5e6) — simssa 量化实证

### 用户洞察: "SSA 阶段常量应该已折叠"
正确 — 根因不是 @WRj+dis16 编码, 而是 **SSA 优化器的常量折叠链断裂**:

### simssa --stats 量化 (新增 Before/Optimized 指令数统计)
| 测试 | 修复前折叠率 | 修复后 | keil_size |
|------|------------|--------|-----------|
| 11_cmp_lt_gt | 51.3% (76→37, br=7/phi=7/add=6 残留) | **98.7% (76→1)** | 773%→**37%** |
| 10_cmp_eq_ne | 部分折叠 | **97.6% (41→1)** | 373%→**37%** |

### 根因: pass_const_branch 的 term 取错
- 块 instrs 末尾有 **NOP 化 phi 残留** (pass_phi 简化产物)
- pass_const_branch 用 `list_get(b->instrs, len-1)` 取 term → 拿到 PHI → **跳过所有 br**
- 常量条件分支 (br v6/v13/v21...) 全部不折叠 → 死块不消除 → phi 单臂不折叠
  → add 累加链不传播 → 37 指令冗余链 (vs Keil 1 条)

### 修复
`pass_const_branch` 改用 `block_last_effective_instr` (跳过 NOP/PHI)。

- Suite 65/0 全绿 + Execute 106/106 全绿
- keil_size TOTAL: 304% (M3) → 254% (@WRj+off) → **248%**
- 常量折叠类测试 (00-13) 已与 Keil 相当或更优 (36.7%)
